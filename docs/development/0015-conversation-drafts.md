## 核查与最小范围

重新阅读 ADR-0001 并核对 Git 与真实组件。ConversationPanel 按会话 ID 挂载 Chat，切换或搜索隐藏会话会卸载输入区，原 content 与 pending requestId 随之丢失。恢复草稿若只保留文字，会让未确认消息以新 UUID 再次发送，因此草稿和未确认输入必须共同保留。

本轮只修改 React 工作台内存状态，继续复用现有聊天提交 / 错误分类 / 原生 requestId 去重。Rust、Runtime、Models、持久化数据与协议均不改变。

- 工作台以既有 Conversation ID 为键保存非空草稿；切换、搜索隐藏再返回时恢复原文字，多行及空格保留。清空输入即删除该会话内存草稿。
- 提交前保存完整原业务输入（请求 UUID、会话、Provider、Model、内容）。结果未知时恢复原请求并锁定修改，点击既有“重试同一请求”核对，不能以新 UUID 重发。
- 成功确认后删除自身请求的草稿；明确拒绝则保留文字并释放原请求，以便修改后正常发送。结算只匹配同一会话及同一 UUID，迟到成功不能清除另一会话或后来的草稿。
- 结算内存草稿可在原 Chat 卸载后完成；mounted 保护仍限制旧组件的 React 状态更新。异步发送、状态轮询与 Durable 的执行机制均不重写。
- UI 明确提示仅在本次打开期间保留。草稿及业务输入均不写入 localStorage、sessionStorage、文件、Transcript 或 SQLite；服务商密码框仍由原设置组件管理，不接入草稿状态。
