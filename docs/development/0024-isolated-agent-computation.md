# Agent 隔离计算

日期：2026-11-28。基于 c4e6420，开发前重新阅读 ADR-0001。用户要求加入沙箱，同时保持代码简洁、减少无必要实体和测试。

## 检查结论与实现

已有工作目录只读授权限制，但未安装 Agent 工具或执行沙箱。检查已安装的 Pi Durable / pi-codemode 1.5.0：原生 CodemodeSandbox 在独立 Worker 中运行 QuickJS / WebAssembly，createCodemodeExtension 已提供工具执行、日志、会话存储与恢复。因此直接复用，不增加沙箱管理类、数据库、Agent Loop 或 Scheduler。

- DurableHost 安装原生扩展，共享既有 Harness / Models，并在关闭时释放沙箱。全局默认 extensions 设为空，注册本身不授予任何会话使用权。
- 输入区提供“沙箱计算”开关，普通聊天默认关闭。提交通过已有 conversation.chat.submit，权限选择与用户输入共同落盘并纳入 requestId 幂等冲突检查。历史输入没有 sandbox 字段时视为关闭，无迁移。
- 每次执行是全新 Worker / VM；原生 store / load 按 Conversation 持久化，恢复与分支语义沿用 Durable。不开放 Models 辅助接口、宿主工具或 ExecutionEnv，因此脚本无法读本机文件、执行 Shell、联网、读取环境变量或凭据。
- 每个 VM 限 32 MiB，脚本最多 16000 字符；原生源码选项强制限时 3 秒、输出 1024 token，模型可以缩小但不能放宽。原生 start 不使用构造器默认期限，故必须在原生源码选项中明确设置期限。
- 每次发送最多三轮模型请求，使用原生 maxTurns；工具顺序执行。最多同时存在两个 Worker，名额直到线程实际退出后释放，防止超时返回提前释放造成积压。所有限制均在 Node 执行，React 不作安全判断。
- Harness 继续限制工具结果为 16 KiB / 200 行。不提供临时文件写入环境，超量完整输出不落宿主磁盘。Native Codemode 自身的输出缓存另有上限。
- 聊天状态投影原生工具阶段为“正在计算”；历史折叠显示代码、按纯文本显示结果。未确认提交沿用原权限重试，切换会话仍沿用既有迟到结果保护。没有新增 IPC 方法、Rust 命令或持久业务实体。

这是实际的 JavaScript VM 隔离，不是把字符串路径检查称为沙箱；也不声称对本机 Shell / 任意原生程序提供容器或操作系统隔离。本轮未启用 Shell、文件读写或网络桥接。工作目录预览仍是人工只读，不自动发送给模型。

## 验证

仅补充两项 Runtime 集成与一项页面回归，复用原夹具，不另建测试体系：

- 真实本地模拟服务商 → Durable 工具调用 → QuickJS → 模型最终回复，验证 process / require / fetch / WebAssembly / models 不存在、node:fs 导入失败、构造器不能获得宿主 process、会话存储独立和 VM 全局不残留；重启后工具结果与开关保留，重复请求不重复调用，权限变更使用相同 requestId 被拒绝，关闭开关移除模型工具。
- 死循环不能绕过期限、内存耗尽只影响当前脚本、输出受限、原生停止中断工具后仍能继续计算；连续工具调用由原生轮数上限结束。
- 页面验证开关、会话切换、未知结果重试权限一致、计算状态与轮数限制提示，以及代码 / 结果纯文本显示，HTML 不执行。

- runtime:typecheck、100 项 runtime:test、build 通过；71 项页面测试全部通过，无失败或跳过。
- 未修改 Rust，仍检查 cargo fmt --check 和 cargo test -- --test-threads=1，11 项全部通过，包含真实 RuntimeClient / JSONL / 新版 DurableHost 启动与现有持久化、工作目录读取链路。
- 隔离页面夹具检查明暗主题和 390px 窄窗，沙箱开关、折叠代码、纯文本结果均可操作。预览文件与临时夹具不纳入仓库。
- 现有 pnpm tauri dev 窗口前端已热更新；Node 子进程不会随 TypeScript 文件自动重载，使用新工具前需重新启动桌面。未关闭现有窗口，以保留可能存在的内存草稿。没有用正式会话或真实密钥发送付费模型请求。
