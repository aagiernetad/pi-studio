# V0.4.0-A1：正式界面起步与工作区导航

日期：2026-11-26。基于已推送的 `0ad281e feat(conversation): 从助手回复分支新建会话`。

## 现状与阶段安排

V0.3.x 已验证服务商 / 凭据、持久会话、模型聊天、停止继续、Markdown、标题搜索、用量、上下文重置和分支。原 App 将会话、设置、Runtime 信息、Ping 和原始事件放在同一长页面，仍属于功能验收界面。仓库此前没有确定正式页面的版期。本轮结合用户询问，将 V0.4.0 定为正式界面开发阶段，先落地最小导航增量。

- A1（本轮）：独立会话 / 服务商 / 诊断入口，默认会话工作台，复用已有组件与深色样式，保护页面切换中的草稿和请求。
- A2（下一步）：完善会话消息区与输入区布局，将日常对话阅读和技术记录查看的入口安排清楚，保留历史分页与分支等现有操作。
- A3（随后）：完善服务商设置页的操作组织及空状态、错误状态，再完成整套界面的桌面回归。

这些是开发阶段标记，不代表已完成整个 V0.4.0 或发布安装包。本轮不新增 Router / Worker、工具权限或执行机制，也不为未实现能力放置假入口。

## 实现边界

实施前重新阅读 ADR-0001 与项目约束，核对真实 Git、App、聊天 / 服务商组件及现有测试。React 仍只通过原有 Tauri Commands 请求数据；Rust、Node、Durable Storage、Models、持久化格式与协议不改动。

- App 增加“会话 / 服务商 / 诊断”工作区导航，当前入口带 aria-current 与对应区域标记；诊断保留现有 Runtime 信息、Ping 和事件。默认只展示会话，设置与诊断进入各自页面查看。
- 会话区域只隐藏、不卸载，保留当前会话、输入草稿、分页、生成轮询及待确认请求的业务 UUID；切页不停止生成、不重复提交。返回时仍可使用原有停止 / 继续 / 幂等重试。
- 服务商区域按进入页面挂载、离开卸载，非受控密码框随之清空。保存 / 删除 / 测试 / 配置写入期间通过已有忙碌状态禁用导航，避免离开时丢失操作结果。
- 从设置离开时通知既有聊天目录 effect 重新查询 Provider / Model，不重建聊天组件或提交消息；保留当前有效选择和草稿，迟到目录请求仍由已有取消标记淘汰。
- 长页面导航固定在可视区域，切换入口返回页首；保留窄屏、键盘与焦点样式。没有引入路由库、全局状态框架或新 API。
