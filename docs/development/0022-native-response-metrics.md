# 每条回复的原生请求统计

日期：2026-11-28。基于 010be31，修改前再次阅读 ADR-0001。

## 数据来源与范围

核对已安装 pi-ai 1.5.0 的 AssistantMessage.durationMs 与 AssistantMessageEventStream 实现：完成消息由原生单调时钟记录请求耗时，旧消息及部分延迟获取的响应可能没有该字段。现有 Durable Transcript 和 conversation.entries 已原样保留它与 usage，不需要新计时器、数据库、IPC 或模型调用。

- 新增 ResponseMetrics，在成功完成或达到长度限制的助手回复下显示耗时、正整数输出 token；按每条回复的原生字段读取，不读取当前选择模型，也不累计历史。
- 耗时包含请求等待和推理，不称为首字延迟、纯生成耗时或生成速度。输出是 pi-ai 标准化 output，已经包含 reasoning 子集，不重复相加。
- 两项独立显示；缺失、负数、非有限值和无效输出不显示。原生四舍五入到 0 毫秒时展示 <1 毫秒，不冒充零延迟。失败 / 停止记录不显示成功请求统计。
- 沿用现有正文复制、分页、会话切换隔离和主题变量。复制回复不夹带统计或思考内容；窄窗自动换行。

## 验证

发布前 runtime:typecheck、93 项 runtime:test、build 与 66 项完整页面回归全部通过，无失败或跳过。新增覆盖真实字段口径、推理不重复计数、缺失 / 非法计量、失败 / 停止过滤、正文复制、历史数据不受模型选择影响及明暗窄窗。

新增页面测试首次使用了不存在的 CSS 选择器，改为既有“选择模型”无障碍按钮后对应测试通过；没有修改生产行为来迁就测试。

真实本地 SSE 回归同时确认原生 durationMs 穿过现有安全流适配、Durable 存储与重启后仍是有效计量。使用隔离页面夹具检查深浅主题及窄窗截图；合成内容只用于预览，不进入正式会话或 Git。

该步骤不修改 Rust 或 Runtime 执行逻辑。运行中的 pnpm tauri dev 已收到前端热更新；验证不读取正式会话内容，不使用正式凭据，不向外部模型发送请求。
