# Prism 对齐：接入模型原生推理档位

日期：2026-11-26。延续 0018 的外观与阅读功能，仍基于本地 31ef4fa 上未提交的工作区。

## 实际问题与最小方案

重新阅读 ADR-0001 后核对本地代码：Model 目录已有 reasoning，但聊天提交仍固定 thinkingLevel 为 off。已安装 pi-ai / pi-durable 均为 1.5.0。pi-ai 的 getSupportedThinkingLevels 按 reasoning 和 thinkingLevelMap 返回实际可用档位，包括不能关闭推理和扩展档位；Durable 的 configure / AgentDoc 已拥有档位持久化和执行能力。

本轮沿原链路接入，不新增 Provider Registry、数据库、Agent Loop、Scheduler 或 Rust 命令。自定义服务商现有配置仍声明 reasoning: false，不擅自猜测兼容端点的能力。

## 功能与兼容

- model.list 增加白名单字段 thinkingLevels，直接读取共享 Models，不访问认证或远程模型。
- 输入区模型胶囊打开的菜单增加离散推理滑杆；只显示该模型支持的档位，不能关闭推理的模型从首个可用档位起步。仅有 off 的模型不显示滑杆，只有一个推理档位时展示固定值。
- 胶囊显示非 off 的当前强度；选择本身不调用模型。目录、模型切换时不会把另一模型的无效档位带入请求。
- conversation.chat.submit 接收可选 thinkingLevel，省略兼容为 off。严格验证枚举与模型能力，凭据读取后、提交落盘前再次核对能力；不支持时不新增输入或调用模型。
- 档位进入原生 configure 和输入元数据；status 读取 AgentDoc。恢复 / 继续生成使用原配置，保持 Durable 的原生调度。
- 请求幂等比较包含档位。历史输入缺少该元数据时按 off 解释；已确认请求即使凭据 / 目录失效仍可核对原提交，改用另一档位会返回 REQUEST_ID_CONFLICT。
- 未确认发送的档位随现有草稿请求保存于本次进程内，禁止在重试前修改；不写浏览器持久存储。停止、恢复、上下文重置和会话分页逻辑继续复用。
